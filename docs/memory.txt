## 1. Create a reusable Memory data model

Create a local mock data file, for example:

`src/data/memories.ts`

Define a TypeScript type/interface for `MemoryRecord`.

Display-model sketch below incorporates the fields already present in `src/data/memories.ts`. `sourceAuthority`, optional `legalRights`, and `consentWithdrawal` are existing display fields, not new implementation work. The marked additions are proposed metadata targets and are not yet implemented. Structured authorizations, evidence, and copy/lifecycle controls belong in `docs/ethos.txt` §4, not in free-text UI fields.

```ts
type MemoryMedia = {
  type: "image" | "audio" | "video" | "none";
  src?: string;
  alt?: string;
  caption?: string;
  duration?: string;
  credit?: string;
};

type RelatedNode = {
  // Metadata relationship only; does not appoint a custodian or grant authority.
  label: string;
  type: "Person" | "Place" | "Theme" | "Institution" | "Language";
  href?: string;
};

type MemoryRecord = {
  id: string;
  recordId: string;
  archiveStatus: string; // Evidence-backed for real records; illustrative for demos.
  lastReviewed: string;
  accessLevel: string;
  confidenceLevel?: string;
  multipleVersions?: string;
  translatorNotes?: string;
  disputedDetails?: string;
  communityAnnotations?: string;
  // Proposed additions; not current runtime fields:
  recordKind: "demo" | "pilot" | "collection";
  demonstrationNotice?: string;
  authorityStatus: "identified" | "shared" | "disputed" | "unknown";
  legalRightsStatus: "identified" | "disputed" | "unknown";
  collectors: string[];
  subjects: string[];
  signerCapacitySummary: string;
  permittedUses: string[]; // Use-specific safe summary; full grants in registry.
  accessRestrictions: string[];
  verificationSummary?: string; // What was checked and its limits, not a score.
  // Existing display fields continue below:
  title: string;
  summary: string;
  location: string;
  language: string;
  era: string;
  contributor: string;
  sourceAuthority: string; // Cultural/intellectual authority, distinct from collector.
  legalRights?: string; // Separately identified applicable legal rights where known.
  consentStatus: string;
  consentWithdrawal: string; // Requester, contact, scope, and disclosed retention limits.
  provenance: string;
  rightsUsage: string;
  sensitivity?: string;
  media: MemoryMedia;
  transcript: string;
  culturalContext: string;
  tags: string[];
  relatedNodes: RelatedNode[];
  relatedMemories: {
    title: string;
    summary: string;
    href: string;
  }[];
};
```

The historical prototype called for at least 3 demo memory records. These examples are now in the local data file; they are demonstrations, not collected testimony:

Every index card and detail page must visibly state “Demonstration record — illustrative content, identities, provenance, and permissions; not collected archival testimony.” Reserve “Verified,” granted-consent claims, review dates presented as real events, and institutional record counts for evidence-backed material. If illustrative status fields remain, label them as examples wherever shown. Keep demo identifiers distinct from accessioned records and exclude demonstrations from pilot results, collection totals, donor evidence, and impact measures.

Existing examples:

* `lagos-port-harcourt-migration`
* `rain-season-enugu`
* `market-song-lagos`

The existing `/memories/demo` may redirect to or render the Lagos migration record.

## 2. Build a reusable MediaViewer component

Create:

`src/components/MemoryMediaViewer.tsx`

Requirements:

* If media type is `"image"`, render a large archival image frame.
* If media type is `"audio"`, render an HTML5 audio player inside a styled archival card.
* If media type is `"video"`, render an HTML5 video player with controls.
* If media type is `"none"`, render a restrained placeholder that says:
  “No public media attached to this record.”
* Always show caption and credit if available.
* Styling should match existing TIRO visual system.
* Use semantic HTML.
* Keep it accessible.
* Do not autoplay anything.

Placement:
On the Memory detail page, place the media viewer after Provenance/Consent and before Transcript.

Rationale:
The display should establish record kind, provenance, and permission scope before media consumption. For demonstrations, explain that all such evidence is illustrative; the visual design must not imply an actual interview or consent receipt.
